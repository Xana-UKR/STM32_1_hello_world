# Instructions for working on this project

Before changing the project or advising the user, read [PROJECT_SPEC.md](PROJECT_SPEC.md) for requirements and [PROJECT_JOURNAL.md](PROJECT_JOURNAL.md), README.md for the current state and next steps.

- Explain terminology, connections, and commands in manageable steps for an experienced C++ developer new to Rust and microcontrollers. Prefer simple, maintainable solutions.
- Follow the owner's chat-guided workflow: explain one command or file change before it is made, let the owner run commands and report observations, then discuss results before proceeding. Do not silently create firmware files or batch unexplained steps unless the owner explicitly asks you to act directly.
- Distinguish observations from plans and assumptions. Claim success only when supported by command output or the owner's observations.
- Confirm board pin mappings and tool syntax against applicable documentation or installed tool help. Recheck COM port numbers when needed.
- Before the first flash, explain that it replaces existing target firmware. Do not erase unrelated content or change hardware configuration without a reason.
- Keep stable requirements and the learning workflow in the specification. Keep the README as a reproducible newcomer guide with steps, PowerShell commands, short explanations, tested tool versions, and no firmware source listings.
- Use the journal as the working record of decisions, commands, failures, evidence, unverified items, and the next actionable step. Update it after a completed stage or another meaningful change, using the user's local date. Transfer verified repeatable instructions into the README at milestones and polish it at the end; keep both files concise.
